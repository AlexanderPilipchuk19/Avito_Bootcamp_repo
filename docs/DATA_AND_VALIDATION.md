# Данные и протокол валидации

## Роли источников

В проекте разделены три источника с разными назначениями. Синтетика давала контролируемые пары для локально обучаемой исследовательской ветки. TextOCR обеспечивал реальный scene-text протокол. Competition test использовался только для статистического аудита входов и финального инференса.

Финальная PP-LCNet x0.25:

- не обучалась на competition test;
- не обучалась на созданной в проекте синтетике;
- не дообучалась на TextOCR;
- использует готовые официальные pretrained weights.

Исследовательские B2/B3/B4 обучались локально на синтетике с опциональной долей real-general TextOCR. Их checkpoints в публичную финальную сборку не включены.

## Аудит competition test

Аудит выполнен для всех 20 000 изображений без чтения или вывода целевой ориентации. Измерялись width, height, area, aspect ratio, цветовой режим, контраст, энтропия, Laplacian variance и edge energy. Все входы были RGB, alpha отсутствовал.

| Наблюдение | Значение |
|---|---:|
| высота `<24 px` | 3 304 изображения, 16.52% |
| aspect ratio `>10` | 2 806 изображений, 14.03% |
| aspect ratio `>20` | 324 изображения, 1.62% |
| почти монохромные | 4 228 изображений, 21.14% |
| точные дубликаты | 0 |

Визуально домен включал scene text, вывески, адреса, логотипы, упаковку, ценники, латиницу, кириллицу и цифры. Индикаторы blur не считались истинной разметкой качества. Поиск near-duplicates был консервативным и мог как пропустить связанные кропы, так и отметить визуально похожие, но разные изображения.

Статистика геометрии использовалась при настройке распределений генератора.

## Синтетические данные

Генератор v1.1 создавал стили `address_plate`, `advertising`, `logo_like`, `packaging`, `price_tag` и `sign`. Текст сначала отрисовывался в правильной ориентации, затем применялись поверхность, небольшая геометрия, освещение, blur, уменьшение, шум, JPEG и композиция кропа. После всех преобразований второй член пары получался точным `ROTATE_180`.

Такой порядок важен: оба класса содержат один и тот же набор пикселей и отличаются только ориентацией. При независимом применении деградаций модель могла бы выучить побочный признак класса.

Simple synthetic служила контрольным вариантом с более простой отрисовкой. На одинаковом протоколе B4 realistic v1.1 получила TextOCR dev Brier `0.251392`, simple - `0.280964`. Выигрыш реалистичного варианта подтверждает полезность совокупности преобразований, но не позволяет приписать эффект отдельному blur, фону или шрифту.

## TextOCR

TextOCR - источник реальных текстовых фрагментов в естественных сценах. Upright-кроп восстанавливался из семантического порядка вершин, а класс 180° создавался точным поворотом. Связанные фрагменты одной сцены оставались в одной исходной группе.

В доступном наборе TextOCR преимущественно представлен латинский текст. Проверенной реальной кириллической validation не было. Поэтому TextOCR проверяет перенос на реальные изображения, но не закрывает языковой риск.

## Разбиения по исходным группам

Разбиение выполнялось до поворотов и аугментаций. Все связанные кропы и обе ориентации одной исходной сцены оставались в одном split.

```text
train       → обучение B2/B3/B4
             (финальная PP-LCNet здесь не обучалась)

dev         → выбор модели, симметрии и runtime

calibration → только подбор scalar temperature T

pipeline lock

holdout     → однократная внутренняя проверка после lock

competition test → только финальный инференс
```

Проверка идентификаторов групп дала:

| Пара | Пересечение групп |
|---|---:|
| dev / calibration | 0 |
| dev / holdout | 0 |
| calibration / holdout | 0 |



## Состав исследовательской обучающей смеси

Для B4 проверялась ограниченная сетка TextOCR при фиксированном бюджете:

| TextOCR в смеси | TextOCR dev Brier |
|---:|---:|
| 0% | 0.251392 |
| 5% | 0.248635 |
| 10% | 0.250130 |
| 20% | 0.250549 |
| 5%, второй seed | 0.250277 |

Доля 5% стала рабочим вариантом только для B4. Неполное воспроизведение на втором seed не позволяет называть её оптимумом. Реальная кириллица во всех вариантах составляла 0%.

## Измеренный synthetic-real gap

Генератор хорошо приблизил геометрию, но не внешний вид:

| Признак | Синтетика | Competition test |
|---|---:|---:|
| средняя ширина | 353.08 | 357.60 |
| средняя высота | 65.38 | 64.40 |
| средний aspect ratio | 6.04 | 6.22 |
| средняя энтропия | 4.782 | 6.182 |
| доля почти серых пикселей | 0.555 | 0.405 |
| Laplacian при h=32 | 2591.7 | 1752.8 |

Наиболее заметен разрыв по энтропии и цветности. Поэтому synthetic dev никогда не использовался как доказательство качества на реальном домене.

## Предотвращение утечек

- Сплиты зафиксированы по исходным группам до генерации поворотов.
- Тестовые изображения не включались в train/dev/calibration/holdout.
- Ручная разметка competition test не выполнялась.
- Калибровка использовала только calibration split.
- Holdout был открыт один раз после pipeline lock.
- После holdout модель, веса, preprocessing, symmetry, `T`, backend, OCR и INT8 не менялись.
- Synthetic stress-test выполнялся после фиксации только как диагностика и не использовался для выбора параметров.

## Итоговая область применимости оценки

Dev Brier `0.039221` и holdout Brier `0.040032` относятся к внутреннему TextOCR-протоколу. Они показывают стабильность на реальном общем сценическом тексте в рамках этих групп.
